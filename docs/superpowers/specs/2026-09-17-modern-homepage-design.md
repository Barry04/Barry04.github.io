# Barry 博客现代化首页设计

## 目标

把当前以 Markdown 表格为主体的首页重构为现代、克制、具有个人辨识度的科技 Bento 首页，同时：

- 保留首页、归档、关于及所有现有文章入口；
- 保留 Jekyll 源仓和 GitHub Pages 从 `master` 根目录构建的方式；
- 同时提供完整的深色与浅色主题；
- 在桌面、平板和手机上保持清晰的信息层级；
- 支持键盘导航、可见焦点和减少动态效果偏好。

## 视觉方向

采用用户确认的“科技 Bento”方向，但不做成管理后台。

基调：

- 深色主题以墨绿黑为主，浅色主题使用冷灰白；
- 青蓝用于品牌与交互状态，红橙只做少量提示；
- 使用当前字体组合，标题强调紧凑无衬线与等宽标签；
- 卡片采用统一圆角、细边框和克制的层次，不使用厚重玻璃拟态；
- 背景保留极淡工程网格，但降低存在感，避免抢正文。

## 信息架构

### 顶部导航

- 左侧保留 Barry 品牌名与状态点；
- 右侧保留首页、归档、关于和主题切换；
- 导航继续保持 sticky；
- 当前页面有明确状态，所有交互目标不小于 44px。

### 首屏

- 小标签：`PERSONAL LOG / AI ENGINEERING`；
- 主标题：`构建、验证，然后写下来。`；
- 一段简短说明，交代内容范围：存量系统、Agent 工程和长期实践；
- 提供 GitHub 与关于页入口；
- 右侧或底部放轻量状态信息，如站点域名、当前年份和文章数量，不伪造订阅量或阅读量。

### Bento 内容区

- 最新文章占据最大卡片，显示日期、标签、标题与一句摘要；
- 次新文章使用中等卡片；
- 归档入口使用小卡片，显示真实文章数量；
- 关于作者使用小卡片，承担个人辨识度；
- 卡片整体可点击，具备 hover、focus-visible 和 active 状态；
- 不依赖 hover 才能理解内容。

### 完整文章列表

- Bento 下方保留完整文章入口；
- “现在”与“学生时代”继续分组；
- 旧文章不因首页改版而隐藏；
- 日期使用等宽数字，标题保持主要视觉权重，标签作为辅助信息。

## 内容与数据

仓库当前文章不是 `_posts` Collection，首页继续维护显式文章清单，不引入新插件或内容迁移。

`README.md` 改为语义化首页内容，保留 GitHub 仓库直接阅读时的可理解性。首页专属结构使用普通 HTML 与 Markdown 混排；链接仍指向现有 `YYYY/*.md`。

真实文章数量按当前首页清单显示，不加入浏览量、订阅量等仓库中不存在的数据。

## 实现范围

- `_layouts/default.html`
  - 调整首页专属 Hero；
  - 保持文章页与资源页现有结构不变；
  - 为 Hero、Bento 与完整文章列表增加明确的 `section` 和标题关联。
- `README.md`
  - 用 Bento 所需的语义结构替换首页表格；
  - 保留全部现有文章和学生时代分组。
- `assets/css/style.scss`
  - 扩展主题 token；
  - 实现首页 Hero、Bento 卡片、文章列表和响应式布局；
  - 加入 focus、hover、active、reduced-motion 和移动端规则。
- `.gitignore`
  - 忽略 `.superpowers/` 视觉讨论临时产物，避免误提交。

不增加 JavaScript 框架、Jekyll 插件、订阅表单、统计服务或内容数据库。

## 响应式行为

- `>= 1024px`：12 列 Bento，最新文章为大卡片；
- `768px–1023px`：两列布局，卡片重新排布；
- `< 768px`：单列，先首屏、再最新文章、次新文章、归档与关于；
- 375px 宽度不得横向滚动；
- 长标题允许自然换行，不截断核心内容；
- 导航在小屏保持可点击，不塞入额外菜单。

## 深浅色

- 默认继续尊重系统偏好和现有 `barry-theme` 本地设置；
- 深色与浅色分别定义背景、表面、文字、边框与强调色；
- 正文文本对比度至少满足 WCAG AA；
- 主题切换不引起布局跳动；
- 两种主题都单独进行视觉检查，不通过简单反色推断。

## 可访问性

- 保留“跳到正文”链接；
- 使用顺序正确的标题层级；
- 卡片使用真实 `<a>`，支持 Tab 与 Enter；
- `:focus-visible` 清晰可见；
- 颜色不是唯一的信息表达方式；
- 尊重 `prefers-reduced-motion`；
- 图标保留 `aria-hidden` 或明确标签；
- 移动端正文基准字号不低于 16px。

## 验收

1. `bundle exec jekyll build` 成功；
2. 首页、归档、关于及所有文章链接仍可访问；
3. 桌面端至少在约 1440px 宽度检查深色与浅色；
4. 移动端至少在 375px 宽度检查布局和导航；
5. 页面无横向滚动；
6. 键盘可依次访问导航、Hero 链接、文章卡片和主题按钮；
7. 焦点状态清晰；
8. `prefers-reduced-motion` 下不出现不必要动画；
9. 文章页不因首页样式重构而发生明显回归。
